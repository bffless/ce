# Proxy Rule Multi-Method Matching — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a CE proxy rule match a set of HTTP methods via a new `methods[]` field (e.g. `["GET","HEAD"]`), backward-compatibly, so HEAD/GET (and similar) can share one rule.

**Architecture:** Additive — add a nullable `methods` jsonb column alongside the existing single `method`; matching precedence is `methods[]` → `method` → any. The method-matching and dedupe logic is extracted into a small pure, unit-tested helper (`method-match.ts`) and consumed by the request matcher and the service. `methods` is threaded through DTOs, service create/import/copy, the MCP tool, and the admin UI (multi-select). The proxy-rule response DTO gains `method`+`methods` (fixing a pre-existing type/Swagger gap).

**Tech Stack:** NestJS + Drizzle (Postgres) backend (Jest), React + RTK Query frontend (Vitest), Radix UI. Per `repos/ce/CLAUDE.md`: schema-first migrations via `pnpm db:generate` (interactive — the user runs it).

## Global Constraints

- **Additive, zero-breaking-change.** Keep `method`; add nullable `methods`. No row migration — `ADD COLUMN` only. Existing single-`method` and null-`method` (any) rules behave exactly as before.
- **Match precedence (exact):** `methods[]` when non-empty → else single `method` → else match any. Case-insensitive.
- **Methods enum (exact, both DTO + MCP + UI):** `GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS`.
- **Migration is interactive** — implementers/subagents must NOT attempt `pnpm db:generate`/`db:migrate`. The schema edit is committed; the migration file is generated by the user (Task 7) and committed then.
- **Repo:** `repos/ce`. Backend dir `apps/backend`, frontend dir `apps/frontend`. Branch `feat/proxy-rule-multi-method` (already created; do NOT create a branch). Commit per task (pre-approved). Git from `repos/ce`.

```ts
/**
 * Pure HTTP-method matching for proxy rules.
 *
 * Precedence: a non-empty `methods[]` wins; else fall back to the single
 * `method`; else (neither set) match any method. Case-insensitive.
 */

type MethodShape = { method?: string | null; methods?: string[] | null };

function effectiveMethods(rule: MethodShape): string[] | null {
  if (rule.methods && rule.methods.length > 0) {
    return rule.methods.map((m) => String(m).toUpperCase());
  }
  if (rule.method) {
    return [String(rule.method).toUpperCase()];
  }
  return null; // any
}

export function matchesMethod(rule: MethodShape, requestMethod?: string): boolean {
  const allowed = effectiveMethods(rule);
  if (!allowed) return true; // any
  if (!requestMethod) return true; // nothing to compare against
  return allowed.includes(requestMethod.toUpperCase());
}

/**
 * Stable, case-insensitive signature of a rule's method matching, for
 * duplicate detection. '' == matches any. Order-independent for methods[].
 */
export function methodSignature(rule: MethodShape): string {
  if (rule.methods && rule.methods.length > 0) {
    return rule.methods
      .map((m) => String(m).toUpperCase())
      .slice()
      .sort()
      .join(',');
  }
  return rule.method ? String(rule.method).toUpperCase() : '';
}
```
